# 台股選股工具

抓取證交所與櫃買中心的公開資料，合併成每檔普通股一列，產生 CSV 與一個可互動的
HTML 選股介面。偏向**價值面**與**存股／高殖利率**兩種選股邏輯。

只用 Python 標準函式庫，不需要安裝任何套件，也不需要任何 API 金鑰。

---

## 怎麼用

在這個資料夾按右鍵「在終端中開啟」，然後：

```bash
powershell -ExecutionPolicy Bypass -File run.ps1
```

跑完會自動用瀏覽器打開選股介面。第一次執行約需一分鐘（多數時間花在逐年抓除權息紀錄，
中間刻意間隔 3 秒避免被證交所限流）。

也可以直接呼叫 Python：

```bash
"C:\Users\ryanl\AppData\Local\Programs\Python\Python313\python.exe" twstock_screener.py
```

### 參數

| 參數 | 說明 |
|---|---|
| `--years 10` | 除權息歷史回溯年數，預設 8 |
| `--no-cache` | 忽略當日快取，全部重新下載 |
| `--skip-history` | 跳過除權息歷史，約 10 秒跑完，但沒有連續配息年數 |

## 產出的檔案

```
output/twstock_YYYYMMDD.csv    完整資料，UTF-8 BOM，Excel 直接開不會亂碼
output/twstock_YYYYMMDD.html   互動選股介面，單一檔案、離線可用
output/artifact.html           發布用版本（見下方「分享成網址」）
cache/YYYYMMDD/                當日快取，重跑不會重複下載；可隨時整個刪掉
```

HTML 介面裡有六個策略範本（價值型／存股型／便宜穩健／純高殖利率／成長股／體質優），
也可以自己拉本益比、股價淨值比、殖利率、連續配息年數、配息率、EPS、月營收年增率、
ROE、負債比、毛利率、股價、成交量等條件，點欄位標題排序，按鈕匯出目前結果為 CSV。

**篩選條件會寫進網址**：條件一改，網址列同步更新，直接把網址傳給別人就能重現同一個畫面。
右下角的「複製篩選網址」按鈕可一鍵複製。

**表格預設顯示前 500 檔**，按「顯示全部」可展開。這是效能取捨——重繪成本由儲存格數量
決定（1972 列 × 24 欄約 47000 格），500 列排序約 174 ms、全部展開約 610 ms。
`content-visibility` 與 `table-layout:fixed` 兩種做法都實測過，前者只快 7%、後者反而更慢，
所以改用上限加按鈕。匯出的 CSV 一律是完整的篩選結果，不受顯示上限影響。

代號與名稱兩欄在橫向捲動時固定於左側，24 個欄位在手機上也不會失去對照。

**排序**：預設依殖利率由高到低。計數列旁的膠囊會顯示目前排序方式（例如「依 殖利率% 由高到低 ▼」），
點它可反轉方向；點表格欄位標題則改換排序欄位，該欄標題會整格反白。
**沒有資料的股票一律排在最後**，不論升冪或降冪——虧損公司沒有本益比，若把空白當成 0，
遞增排序時它們會全部衝到最前面看起來像最便宜的股票。
結果超過 500 檔時，計數列會出現提示：表格只畫前 500 列，完整清單要匯出 CSV。

**產業別篩選**：可勾選多個產業（面板內附搜尋框與各產業檔數），勾「改為排除所選」則反過來
把它們濾掉——例如想避開營建股，就選「建材營造」再切換成排除。不勾任何一項＝不限產業。
結果下方的產業分布膠囊也可以直接點擊，快速鑽進該產業，再點一次退回。

**名詞解釋**：篩選條件旁的 `?` 圖示、以及表格的欄位標題，滑鼠移上去會顯示該指標的定義、
算法與判讀時的陷阱。`?` 也可以用鍵盤 Tab 聚焦顯示。全部定義集中在 `template.html`
的 `TIPS` 物件裡，要改文字只需動那一處。

## 公開網址（GitHub Pages）

**<https://leeeeeder.github.io/twstock-screener/>**

這是要給別人看的網址。不需要帳號、不需要登入，每個交易日自動更新。
CSV 也一併部署在 `twstock_latest.csv`。

`.github/workflows/daily-refresh.yml` 抓完資料後直接部署到 Pages，所以資料一更新，
訪客重新整理就看得到，中間沒有任何人工步驟。

服務的是 `output/index.html`（**完整的 HTML 文件**），不是 `output/artifact.html`
（那是剝掉 `<html>`／`<head>`／`<body>` 的片段，只能在 Artifact 的外層骨架裡運作，
單獨放到網站上會壞掉）。兩個檔案由同一份 `template.html` 產生。

### 為什麼不用 Artifact 分享

Artifact 的分享機制對這個用途有兩個硬限制，合起來讓它無法用於「每天自動更新給別人看」：

1. **公開連結會釘住版本。** 訪客永遠停在你按分享當下那一版，之後的更新不會傳達過去，
   而且**不會有任何錯誤提示**。想改成跟隨 Latest 會被擋下：
   「Can't switch to Latest while shared publicly. Change who has access first.」
2. **存取名單只能有擁有者。** 分享對話框的「People with access」沒有邀請他人的功能，
   所以「限定特定人 + Latest」這個組合實際上不存在——選了限制模式就等於只有你自己看得到。

外加一項：Artifact 的檢視器會封鎖頁面發起的下載，要匯出 CSV 就得宣告 `downloads` 能力，
而宣告任何能力又會禁止公開分享。Pages 沒有這些限制，**匯出 CSV 在網站上可以正常使用**。

Artifact 版本的網址仍在，但**每日自動發布的排程已停用**
（`trig_01GshEoE1KqDfaHr7HLFdjwJ`，管理頁面 <https://claude.ai/code/routines>），
因為 Pages 已經完全取代它的用途，繼續跑只是白花 Claude 用量。
排程設定保留著，想恢復隨時可以啟用。

## 分享成網址（Artifact，次要）

`output/artifact.html` 是發布用的版本，內容與本機版完全相同，差別只在**去掉了
`<!DOCTYPE>`／`<html>`／`<head>`／`<body>` 外層標籤**——Claude Artifact 會用自己的骨架
包起來，頁面檔案只能放內容本身。`<meta charset="utf-8">` 有刻意保留：少了它，
若外層沒宣告編碼，瀏覽器會退回 Latin-1，中文全變亂碼。

檔名固定不帶日期是刻意的。重新發布**同一個檔案路徑**會蓋回同一個網址，
所以資料更新後重發，已經分享出去的連結不會失效。

目前的網址：<https://claude.ai/code/artifact/ffc437ba-4048-4a89-9302-228df7244344>

### 自動更新

每個交易日自動更新，不需要開電腦。分成兩段，各自跑在能做該件事的地方：

| 時間（台北） | 誰 | 做什麼 |
|---|---|---|
| 18:00 | GitHub Actions（`.github/workflows/daily-refresh.yml`） | 抓交易所資料、重建頁面、把 `output/artifact.html` commit 回 repo |
| 18:30 | Claude 雲端排程 `trig_01GshEoE1KqDfaHr7HLFdjwJ` | clone repo，把那個檔案發布到既有網址 |

**為什麼要拆兩段。** Claude 雲端沙箱的出口代理只放行開發用途的網域
（anthropic.com、npm、pypi、crates），連交易所會被擋掉：

```
urlopen error Tunnel connection failed: 403 Forbidden
  https://openapi.twse.com.tw/...
```

GitHub-hosted runner 則沒有這個限制。所以抓資料放 Actions，發布放雲端排程——
後者只需要 clone，而 clone 走的是 GitHub，不受那道代理影響。

排程管理頁面：<https://claude.ai/code/routines>

兩邊都有「資料不完整就不要往下走」的檢查，理由見下方。排程的指令裡也寫死了
**不傳 `capabilities`**（省略才會沿用既有的 downloads 授權，傳 `{}` 會清掉，
訪客就不能匯出 CSV）與**不傳 `contract`**。

前置作業（只需做一次）：Claude GitHub App 必須安裝在 `leeeeeder` 帳號並涵蓋這個 repo，
否則建立排程時會回 403。

### 為什麼要擋「不完整」的結果

第一次的 Actions 執行拿到了櫃買的 889 檔，但證交所全軍覆沒，於是產生一個
「上市 0 檔」的頁面——而當時的檢查只驗檔案非空，889 檔確實非空，所以它被 commit 了。
**一個非空的檔案不等於一個完整的檔案。**

後續查證：curl 與 urllib 從 runner 連證交所都是 HTTP 200，換過三種 User-Agent 也都正常。
所以那不是封鎖，是**速率限制**——腳本把約 10 個證交所端點連續打完，整批被拒，
而櫃買在另一台主機上完全不受影響。

因此有兩道防線：

1. `twstock_screener.py` 若任一市場完全沒抓到就 exit 2，不產生檔案（`--allow-partial` 可覆寫）
2. workflow 與雲端排程都會在動作前檢查上市 ≥ 900、上櫃 ≥ 700

以及兩道預防：

- `fetch_json()` 對同一主機強制間隔 1.5 秒，重試退避 5／10／15 秒。
  整趟約多花 15 秒，換掉整個失敗模式
- `fetch_json()` 攔截 `OSError` 與 `http.client.HTTPException`。
  先前只攔 `URLError`／`JSONDecodeError`／`TimeoutError`，結果 4 MB 的上櫃行情檔
  下載到一半中斷時，`IncompleteRead` 直接往上炸掉整支腳本，連重試都沒有

**檢查程式本身也會過時。** 改成欄位陣列格式後，workflow 那段驗證用的正規表達式
（假設 `"rows"` 緊接在 `"meta"` 之後）就對不上了，整個 job 失敗。
失敗總比部署壞資料好，但檢查不該依賴欄位順序——現已改為只比對 meta 自己的大括號。

### 分享方式決定訪客會不會拿到新資料

分享對話框裡的「Shared version」有兩種狀態，而它跟「General access」是互斥的：

| General access | Shared version | 結果 |
|---|---|---|
| Anyone with the link | 只能釘選特定版本 | 訪客永遠停在你按分享當下那一版 |
| Only people with access | 可選 **Latest** | 但存取名單只有擁有者，等於只有自己看得到 |

想改成 Latest 但 access 還是公開時，介面會擋下來並顯示
「Can't switch to Latest while shared publicly. Change who has access first.」

關鍵在於**「People with access」沒有邀請他人的功能**，名單裡永遠只有擁有者。
所以「限定特定人 + Latest」這個組合實際上不存在：選了限制模式就等於誰都看不到。
兩個條件無法同時滿足——別人看得到，就一定停在釘選的版本，而且**不會有任何錯誤提示**。

這正是最後改用 GitHub Pages 的原因。

### 為什麼分享版不能匯出 CSV

**宣告任何執行期能力（capability）的 artifact 都不能被公開分享**，`downloads` 也算。
平台的錯誤訊息是「This artifact uses connectors, so it can't be shared publicly」，
用詞容易誤導——它指的是任何能力宣告，不是只有 MCP 連接器。

因為分享才是這個頁面存在的目的，所以發布時傳 `capabilities: {}` 清掉宣告，
放棄訪客端的 CSV 匯出。**排程的指令裡也明確禁止把它加回去**，否則分享會再次被鎖。

補償措施：原本表格只畫前 500 列、靠匯出補足完整清單；沒有匯出之後那會變成死路，
所以改成一次列出全部（全市場不到 2000 檔）。整表重繪約需 0.4 秒，因此篩選欄位的
輸入加了 160ms 防抖，打字才不會每按一鍵就重繪；點擊仍即時反應。

匯出鈕的三條路仍保留在程式裡：

| 情境 | 判斷依據 | 走法 |
|---|---|---|
| 本機直接開檔 | 沒有 `claude` 物件 | blob 連結，直接下載（**完整可用**） |
| 發布版 | `claude.use('downloads')` 回傳 `null` | 按鈕停用並說明原因 |
| 若日後重新宣告 downloads | 取得能力 | 由檢視器跳出確認框後儲存 |

第三條路的程式碼經過實測（含 `.csv` 副檔名未啟用時自動改存 `.txt` 的退路），
保留著以備日後平台政策改變。**本機版的匯出不受任何影響。**

### 產業別的兩段式處理

`t187ap14_*` 直接給中文產業名稱，但**不含金控、保險與 KY 外國企業**（富邦金、亞德客-KY 等會是空白）。
公司基本資料 `t187ap03_*` 涵蓋全部公司，但產業別是數字代碼。

腳本的作法是：先用 `t187ap14_*` 取得「公司代號 → 中文產業名」，再用同時出現在兩個資料集的公司
反推出「產業代碼 → 中文名」的對照表，最後拿它補上缺漏者。**對照表是從資料本身推出來的，
沒有寫死任何產業代碼**，所以交易所日後新增產業別也不會失效。實測 1972 檔全部分類成功。

**名稱統一**：交易所公布的產業名稱本身並不一致——代碼 17 有 39 家標成「金融業」、2 家標成
「金融保險業」（含 2812 台中銀）。若照原樣保留，篩選「金融業」就會漏掉那 2 家。
由於產業**代碼**才是真正的分類、名稱只是它的標籤，腳本以多數決選出每個代碼的正式名稱，
再覆蓋到所有同代碼的公司身上。目前共 34 個產業別。

## 已知限制

這幾點會直接影響篩選結果，用之前要知道：

1. **上櫃的連續配息年數是從 2026-08-16 開始累積的，短期內仍是空白。**
   櫃買中心沒有任何多年度來源：`tpex_exright_daily` 只有當天，
   `mopsfin_t187ap39_O` 停更在民國 110 年，新舊站的日期查詢一律被忽略。
   因此改為每天把當日除權息紀錄存進 `data/tpex_exright_history.json` 自行累積。

   **只有被完整涵蓋的日曆年才會計入連續配息年數**——累積未滿一個完整年度前一律留空。
   幾個月的紀錄如果被當成配息紀錄呈現，會比空白更容易誤導人。
   介面上的「保留無配息歷史者」勾選框仍然有用：套用存股型範本時會自動取消勾選。

2. **ROE 沒有年化。** `115Q2` 是上半年的報酬率，直接乘二在景氣循環股會嚴重失真，
   所以刻意不代為換算。判讀時要看「財報期別」欄確認統計到哪一季。

3. **月營收年增率的單月數字容易被基期扭曲。** 去年同月基期低的話，
   今年表現普通也會出現極高的增幅（資料中最高超過 100 萬%）。
   要搭配「累計營收YoY」一起看。此欄由交易所計算公布，非自行推算。

4. **金控、保險、證券期貨業沒有 ROE 與負債比。** 這些業別的資產負債表端點
   （`_fh`、`_ins`、`_bd`、`_basi`）在開放資料裡幾乎是空的，每個只有 1–4 筆，
   而且欄位時有時無。與毛利率的缺漏範圍一致。

2. **殖利率是回顧型的。** 交易所的算法是「最近一次已發放的現金股利 ÷ 當日收盤價」，
   反映的是過去，不是未來。除息旺季（每年 6–9 月）剛除息完的股票，
   殖利率會顯示為新的一期或舊的一期，取決於交易所何時更新，判讀時要留意。

3. **「EPS 近四季」與「配息率」是推算值。** 兩所都把本益比定義為「收盤價 ÷ 最近四季每股稅後盈餘」，
   所以反推出 `近四季EPS = 收盤價 ÷ 本益比`，再算 `配息率 = 現金股利 ÷ 近四季EPS`。
   分子是最近一次已發放的股利、分母是最近四季獲利，兩者年份本來就錯開，因此配息率是**粗估**，
   用來抓「配息明顯超過獲利」的極端值很有效，但不必計較個位數的差異。

4. **配息率超過 100% 代表配出去的比賺到的多**，差額來自過去累積的保留盈餘或資本公積。
   這在剛完成一波獲利認列的公司（例如營建業交屋年）很常見，本身不必然是壞事，
   但那個配息水準通常**不可持續**。表格中此欄超過 100 會標紅，結果列下方也會顯示總檔數。
   存股型與便宜穩健兩個範本已內建配息率上限。

5. **EPS 累計是當年度累計數。** 例如 `115Q2` 是民國 115 年上半年的累計 EPS，跟 `115Q1`
   不能直接比大小，也不要跟「EPS 近四季」混用——兩欄的期間定義不同。

6. **金控、保險、證券期貨業沒有「營業收入」欄位**，毛利率、營益率與淨利率會留空。

7. **虧損公司的本益比是空白而不是 0**，篩選時「本益比 0～15」會直接把它們排除掉，
   這通常是你要的；但如果想找轉機股，要改用「本益比不設限 + EPS 條件」自己組。
   這些公司也不會有配息率（分母無意義）。

8. 篩選範圍只含**四位數字代號的普通股**，已排除 ETF、ETN、特別股、存託憑證、權證。

9. 這個工具只做數值篩選，**不構成投資建議**。入選只代表「數字符合條件」，
   後面該看的財報、產業循環、公司公告一樣都不能少。

`load_*()` 填值，再到 `template.html` 的 `COLS` 陣列與 `apply()` 加上條件即可。
